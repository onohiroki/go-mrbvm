# go-mrbvm v0.1.3

This release adds bundled applications, an injectable source/asset
filesystem, and the `gomrbpack` command. The VM and core library behavior is
otherwise unchanged.

## Requirements

- `go-mrbc` v0.1.1
- mruby 4.0.0 / RITE 04.00

## Highlights

- Added `mrbvm.Options.SourceFS` and `Options.LoadPaths`. `load`, `require`,
  and `require_relative` read through the injected filesystem, and `require`
  can load `.mrb` bytecode as well as source. `mrbvm.NewSourceFS` adapts any
  `io/fs.FS`.
- Added `$LOAD_PATH`. It is seeded from `Options.LoadPaths`, exposed to Ruby,
  and consulted by `require`; `gomruby` gained `-I`.
- Added `mrbvm.Options.AssetFS`. `File.read`, `File.exist?`, and `File.size`
  prefer bundled assets and fall back to the capability-gated host
  filesystem. Supply `Options.AssetFS` directly, or use `bundle`.
- Added the `bundle` package: a deterministic `.mrbb` ZIP format with
  `manifest.json`, checksum and path validation, limit checks, an embedded
  runtime (`bundle.Run`), `Options.Setup` for registering host APIs before
  the entry point, and `FuzzOpen` coverage.
- Added `gomrbpack`: `pack`, `build`, `run`, `list`, `info`, and `extract`.
  - `.rb` inputs are compiled to RITE bytecode at pack time.
  - `--include` bundles data files for `File.read`.
  - `build` generates a `//go:embed` launcher and runs `go build`, including
    `--goos` / `--goarch` cross-compilation.
  - Default builds omit the compiler (Prism/wazero); `--with-compiler` links
    go-mrbc and permits `eval`.
  - `--strip`, `--trimpath` controls, and `--replace` for local development.
- `gomruby` runs `.mrbb` bundles and detects them by extension or ZIP magic.
- Added bundle benchmarks: `make bundle-smoke`, `make bundle-bench`, and a
  recorded baseline (`benchmark/bundle-baseline-2026-11-28.txt`). CI runs the
  smoke test, and the nightly Bench workflow archives both benchmark files.
- Added `docs/bundling.md` and `docs/bundling.ja.md`.

## Known limitations

- `File.open` does not read bundled assets; only `File.read`, `exist?`, and
  `size` consult `AssetFS`.
- The default generated binary has no compiler. `eval` and source `load`
  require `--with-compiler` or a custom `bundle.Options.Compiler`.
- `ObjectSpace` and precise per-object memory accounting are still pending.
- The existing official-test allowlists and Regexp exclusions are unchanged.
  Bundling does not change VM conformance.
